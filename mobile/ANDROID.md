# Android 테스트 빌드

이 프로젝트는 첫 Android 기기 검증용입니다. 운영 배포 및 Google Play 제출은 아직 구성하지 않았습니다.

## 빌드

Node 22 이상, JDK 21, Android SDK Platform 36 및 Build Tools 35.0.0/36.0.0이 필요합니다.

```sh
cd mobile
npm ci
npm test
npm run apk:staging
node scripts/verify-android-apk.mjs android/app/build/outputs/apk/debug/app-debug.apk
```

`ANDROID_HOME`은 SDK 경로, `JAVA_HOME`은 JDK 21 경로로 설정합니다. 결과는 `android/app/build/outputs/apk/debug/app-debug.apk`입니다. Debug 서명이며 Play 업로드용 AAB가 아닙니다.

앱 이름은 **매니 테스트**, 설치 ID는 `kr.co.manee.app.staging`입니다. 운영 앱의 계정·로컬 저장 공간과 구분되고 `config/environments.json`의 staging 프로젝트에 연결됩니다. 테스트 계정과 가상 데이터만 사용합니다. Android production 웹 빌드와 Gradle release variant는 현재 비활성화했습니다. Gradle은 복사된 웹 자산의 플랫폼·환경을 확인하여 iOS/운영 자산의 혼입을 차단합니다.

## 지원 범위

| 기능 | 이번 버전 |
| --- | --- |
| 로그인·직원·급여·근무표 관리 | 기존 웹 기능을 staging DB에 연결; 실제 기기 확인 필요 |
| 출퇴근 위치 | 사용자 동작 시 Capacitor 위치 요청; 허용/거부/대략적 위치 모두 실제 확인 필요 |
| 사진 첨부 | Android WebView 파일 선택기 사용; 실제 사진 선택 및 저장 확인 필요 |
| AI·영수증 자동 인식 | staging API 미구성으로 사용 중단 안내 |
| 음성 입력 | 사용 중단 안내, 마이크 권한 없음 |
| 푸시 알림 | 1.7에 Firebase 테스트 앱 설정 반영; 서버 인증 정보 연결과 실제 기기 수신 확인 필요 |
| 구독 결제 | 미구현; Android에 APNs/StoreKit 미포함 |
| PDF·엑셀 내보내기 | Android 시스템 저장 위치 선택창 사용; 실제 기기 최종 확인 필요 |

백그라운드 위치·연락처·기기 캘린더·마이크·전체 사진 저장소 접근 권한을 요청하지 않습니다. 앱 안에서 직접 입력하는 직원 연락처와 근무표 데이터는 기기 주소록/캘린더 권한과 별개입니다. 자동 백업 및 HTTP 평문 통신을 비활성화했습니다.

## 휴대폰 확인 순서

1. APK 설치 후 `매니 테스트`가 별도 앱으로 표시되는지 확인합니다.
2. 테스트 계정으로 로그인하고 매장을 선택합니다. 앱 종료/재실행, 로그아웃을 확인합니다.
3. 출퇴근 위치 권한 허용·거부를 각각 확인합니다. 정확한 위치를 거부했을 때 잘못된 출근 기록이 저장되지 않아야 합니다.
4. 테스트 직원·근무표를 작성하고 사진 한 장을 첨부한 뒤 다시 열어 저장 결과를 확인합니다.
5. 키보드, 시스템 뒤로가기, 화면 가장자리, PDF/엑셀 내보내기를 확인합니다.

운영 출시 전에는 미지원 기능의 범위를 결정하고 Google Play Billing/FCM, release 서명 및 AAB 배포를 별도 구성해야 합니다. 실제 출시 기능과 SDK의 데이터 전송을 다시 조사한 뒤 Play 데이터 보안 설문을 최종 제출합니다. 현재 임시 저장된 15개 항목을 이 테스트 APK의 확정 신고로 간주하지 않습니다.

## 테스트 업데이트 1.1 (versionCode 2)

월간 보고서 및 과거 마감 보고서의 PDF·엑셀 파일을 Android `ACTION_CREATE_DOCUMENT`로 저장합니다. 생성 중·저장 완료·취소·실패 상태가 표시되며, 중복 터치로 저장 창이 여러 개 열리지 않습니다. 엑셀은 PDF 엔진·글꼴 로딩에 의존하지 않습니다.

월 마감 확인과 마감 기록을 별도 카드로 정리하고 앱 스타일의 버튼·체크박스를 적용했습니다. 금액 집계와 마감 허용 조건은 유지됩니다.

내부 임시 파일은 앱 캐시에 준비한 뒤 사용자가 선택한 문서에 기록하며 취소·완료·실패 시 제거합니다. 대용량 base64 데이터를 Activity 상태에 넣지 않습니다. 새 저장소 권한은 요청하지 않습니다.

검증: 내보내기 동작 테스트 5개 및 바이너리 전달 테스트 1개, 기존 보고서·비용·알림 관련 테스트, staging 보고서의 PDF 생성과 엑셀 6개 시트 금액 확인, Android 컴파일·서명·패키지 검사를 수행합니다. Android 실기기 저장창 확인은 설치 후 필요합니다. 로컬 브라우저 캡처는 실행 환경의 소켓 권한 제한으로 수행하지 못했습니다.

## 테스트 업데이트 1.2 (versionCode 3)

1.1은 사용자 휴대폰에서 PDF·엑셀 파일 열림과 매출 10,000원 반영을 확인했습니다. 1.2는 월간 보고서 엑셀 6개 시트에 전용 서식을 적용합니다. 긴 한글 항목·설명·거래처명을 줄바꿈하고 행 높이를 지정하며, 금액은 숫자형을 유지한 채 쉼표·원 단위로 표시합니다. 일수·인원·건수는 통화로 표시하지 않으며 미확정 인건비와 수익은 계산 보류로 표시합니다. 기준 시각은 한국 시간(KST)으로 정리했습니다.

PDF의 날짜별·거래처별 별도 페이지는 유지하며 할인·반품 0원에 음수 기호가 붙던 표시를 바로잡았습니다. 저장 경로와 월 마감 조건은 동일합니다. 이번 버전의 Android 뷰어별 줄바꿈·행 높이 적용은 실제 기기에서 최종 확인해야 합니다.

## 테스트 업데이트 1.3 (versionCode 4)

1.2는 사용자 휴대폰에서 PDF·엑셀 열림, 한글 줄바꿈·금액·KST 서식과 월 마감 화면 디자인을 확인했습니다. 1.3은 파일 저장 안내가 상단 저장 영역과 월 마감 카드에 중복 표시되는 문제를 수정합니다. 일반 보고서는 상단, 월 마감 후 PDF는 마감 카드, 과거 보고서 다운로드는 마감 기록 영역에만 진행·완료·취소·오류 안내를 표시합니다. 다른 작업을 시작하면 앞선 영역의 안내를 비우며 화면을 다시 그려도 중복 표시하지 않습니다. 월 마감 여부와 파일 저장 결과는 구분됩니다.

## 테스트 업데이트 1.4 (versionCode 5)

1.3은 사용자 휴대폰에서 상단 엑셀 저장 안내가 하단 마감 카드에 중복되지 않는 것을 확인했습니다. 1.4는 매장 준비 중 ‘저장된 내용 유지하고 홈으로’를 선택한 뒤 앱을 재실행하면 다시 준비 화면으로 돌아오던 흐름을 수정합니다. 이 선택을 기기 내 계정·매장별로 저장하고 재실행 시 홈을 표시합니다. ‘매장 준비 이어하기’ 또는 더보기의 가이드를 누르면 저장된 단계로 돌아가며, 그 뒤부터는 진행 중인 준비 단계를 이어서 엽니다. 서버의 매장 준비 완료 상태와 기존 매출·위치·비용 데이터는 변경하지 않습니다.

이전 버전에는 홈으로 나간 선택이 저장되지 않았으므로 업데이트 후 한 번 선택해야 합니다. 기기 데이터 삭제·다른 기기에는 이 선택이 전달되지 않습니다. 저장 공간 접근 실패는 안내하며 준비 완료로 처리하지 않습니다.

검증: 준비 과정 18개(재실행·이어하기·계정/매장 구분 포함), 월 마감 DB 및 보고서 내보내기 23개 테스트 통과. 월 마감 DB 검증은 로컬 합성 데이터로 매출/급여 누락 차단, 중복 요청 처리, 과거 버전 보존을 확인했습니다. 실제 휴대폰 종료/재실행은 이 APK로 최종 확인이 필요합니다.

## 테스트 업데이트 1.5 (versionCode 6)

1.4는 사용자 휴대폰에서 재실행 시 준비 화면이 다시 나타나지 않는 것을 확인했습니다. 직원 가입·매장 연결·신규 직원 승인·다른 매장 접근 차단·근무표·30분 급여 계산 관련 로컬 자동검증 123개가 통과했습니다. 실제 휴대폰 직원 가입부터 출퇴근까지의 전체 흐름이나 실제 Supabase 동시 승인을 실행했다는 의미는 아닙니다.

1.5는 Android 출퇴근 및 매장 위치 등록 시 정확한 위치 권한을 확인합니다. Android의 대략적 위치는 `enableHighAccuracy`만으로 차단되지 않아, 위치 요청 후 실제 권한을 검사합니다. 정확한 위치 권한이 없거나 좌표가 잘못됐거나 수평 오차가 100m를 넘으면 성공 콜백과 저장 요청을 차단하고 재시도 방법을 표시합니다. 이전 위치 캐시를 쓰지 않도록 `maximumAge: 0`을 지정했습니다. 매장 100m 반경과 서버 출퇴근 시각 계산은 유지합니다. 이 검사는 GPS 오차나 위치 위조가 전혀 없음을 보장하지 않습니다.

매장 설정의 위치 저장도 서버 오류·0행 응답 시 기존 위치를 유지하도록 수정했습니다. 계정·매장 전환 후 도착한 위치 결과는 저장하지 않으며, 서버가 반환한 저장 결과만 화면에 반영합니다.

수정 후 위치·근태·화면 관련 58개 테스트가 통과했습니다(위 123개와 일부 중복). 정상 위치, 대략적 권한, 오차 초과, 잘못된 좌표, 권한 거부, GPS 꺼짐, 시간 초과, 출근/퇴근 요청 차단, 매장 위치 저장 실패를 합성 응답으로 검증했습니다. 실제 Android 권한 화면과 실내 GPS는 설치 후 확인이 필요합니다. 서버 변경·운영 배포·실제 직원 기록 생성은 하지 않았습니다.

기기 확인: ‘정확한 위치 사용’을 끈 상태로 위치 등록/출퇴근을 누르면 설정 안내가 나오고 기존 값이 유지되어야 합니다. 다시 켜고 요청하면 현재 위치를 확인하며, 오차가 크면 창가 등에서 재시도합니다. 테스트 매장의 위치를 등록할 때는 이후 출퇴근을 시험할 같은 장소에서 등록합니다.


## 테스트 업데이트 1.6 (versionCode 7)

매장 준비 1단계 위치 재등록에 진행 중·저장 완료·실패 안내를 추가했습니다. 서버가 반환한 매장 ID와 좌표를 확인한 후에만 완료를 표시합니다. 중복 터치와 매장 전환 중 늦은 응답을 차단하며, 실패하면 기존 위치를 유지합니다. 안내는 같은 화면에서 다시 렌더링해도 남습니다. 재시작 후에는 서버에서 불러온 등록 여부를 표시합니다.

Android FCM 등록·해제·권한 확인·토큰 갱신·로그아웃 정리와 staging 전용 테스트 발송 경로를 준비했습니다. Firebase 설정이 없는 APK에서는 권한 요청이나 토큰 등록을 시작하지 않습니다. 기기의 자동 FCM 초기화도 꺼두었습니다. 알림 켜기를 누르면 준비 상태가 카드에 남고 앱 안의 알림은 계속 동작합니다.

이 APK에는 Firebase 앱 설정이 없으므로 **실제 휴대폰 푸시 수신은 아직 지원하지 않습니다.** Firebase 연결 후 새 APK를 빌드하고 실기기 수신을 확인해야 합니다. 출퇴근·예약·월말 이벤트 자동 발송은 아직 Android 발송 경로에 연결하지 않았습니다. 설정 절차는 [ANDROID_PUSH.md](ANDROID_PUSH.md)를 참고하세요.

검증: 모바일 20개, 위치·준비 과정·Android DB 권한·FCM 서버 50개 테스트 통과(합계 70개). Android 컴파일, 패키지/권한 검사 및 설치된 1.5와 동일한 서명을 확인했습니다. staging에 Android 전용 테이블/RPC/Edge Function을 반영했고 인증 없는 요청의 401 거절을 확인했습니다. 운영 DB·운영 웹·iOS 푸시 발송 경로는 배포하지 않았습니다.

## 테스트 업데이트 1.7 (versionCode 8)

회사 계정의 Firebase `manee-staging` 프로젝트에 Android 테스트 앱을 등록하고 해당 앱의 구성 파일을 적용했습니다. 1.6에서 확인한 매장 위치 저장 안내와 기존 테스트 데이터를 유지하는 업데이트입니다. 서버의 푸시 발송 인증 정보가 연결되기 전에는 알림 활성화를 준비 중으로 표시합니다. 실제 푸시 수신 성공을 의미하지 않으며, 서버 연결 후 실제 기기에서 확인해야 합니다.

검증: 모바일 테스트 20개, Firebase 구성 파일의 프로젝트·패키지 일치 검사, Android clean 빌드, 서명 및 패키지/권한 검사를 통과했습니다. FCM HTTP v1 API 활성화를 확인했습니다. 서버 키 발급 승인과 Supabase 보안 설정 등록은 아직 완료되지 않았습니다.
