# 매니 월말 리포트

매출 → 월간 리포트의 월말 마감에서 실제 세후급여, 영업일 보고, 지출·고정비의 확인 후 마감한다. 실제 급여가 미확정 또는 추정인 경우, 영업 예정일 보고 누락, 아직 월말이 되지 않은 경우는 서버에서 거부한다. 비용 중복 여부는 확인 체크를 요구하고 기존 거래를 추측하여 삭제·재분류하지 않는다.

마감 순간 서버 계산 결과를 변경 불가능한 버전으로 저장한다. PDF는 자동 생성·다운로드하고 엑셀도 같은 마감 버전에서 생성한다. 과거 마감본을 다시 다운로드할 수 있다. 정정할 때는 5자 이상 이유와 새 버전을 남기며 과거 본문은 바뀌지 않는다. 요청 UUID와 매장·월 잠금으로 중복 저장을 방지한다. 사장님·매니저만 마감하며 일반 직원의 마감·마감본 변경을 차단한다.

PDF: 매니 초록색 브랜드, 한글 나눔고딕 임베딩, 요약과 공제 계산, 세후급여·가불, 보험료·원천세 분류, 날짜별 지출·고정비·매출·결제수단·배달 경로 상세, 다중 페이지 자동 나눔과 페이지 번호. 지출 항목명은 포함하되 알려진 직원·사장 이름·연락처·계좌·주민번호가 섞인 항목명은 서버에서 가린다. 원래 메모·직원 식별자·개인정보 컬럼은 보고 API에 포함하지 않는다.

엑셀: 월말 요약, 일별 매출, 지출 상세, 고정비. 기존 직원 정보·거래처 지출·근무/급여 정산 내보내기도 유지한다. PDF/엑셀 모두 저장된 숫자와 상세 합계가 일치하지 않으면 내보내기를 거부한다. 실제 은행잔액이 아닌 예상 순수익이다. 급여는 귀속월, 일반 지출·보험료·원천세는 등록된 지출 날짜 기준이다.

검증: 회귀 577개 중 568개 통과, 기존 9개 건너뜀, 실패 0개. 관리자 신규 UI 5개 통과. 실제 PDF 7페이지 렌더링으로 한글·긴 항목명·정렬·페이지 나눔 검사. 운영 빌드 및 스테이징 preflight 통과. 스테이징·운영 합성 역할 리허설에서 마감 계산·재시도·정정·불변 보존 통과, 검증 데이터 롤백. 본사 원시 개인정보 차단과 마감 수정 권한은 DB에서 강제한다. 실제 휴대폰 로그인·다운로드 조작은 아직 검증하지 않았다.

최종 확인(2026-10-02): 운영 사이트 index.html·PDF 생성 코드·pdf-lib·fontkit·한글 글꼴이 운영 빌드와 바이트 단위로 일치. 재무 RPC 6개의 권한 계산 코어를 private 스키마로 이동하고 public은 invoker 호출만 수행하도록 스테이징·운영에 반영했다. 양쪽 DB에서 합성 역할 월 마감·정정·과거 버전 보존 테스트를 재실행하고 모두 롤백했다. 본사 UI 테스트 5개 통과. 실제 휴대폰 로그인 후 다운로드 조작은 미검증.

## Android 1.10 후속 확인 (2026-10-13)

사용자가 제공한 실제 휴대폰 화면에서 잠정 보고서 PDF 3페이지와 엑셀 열기를 확인했다. 매출 110,000원, 지출 0원에서 지출 1,000원을 추가한 뒤 두 출력의 예상 수익이 109,000원으로 일치했다. PDF 날짜별 상세와 거래처별 요약은 각각 1건·1,000원이며 동일 지출이 이중 차감되지 않았다. 화면에 나타난 범위의 확인이며 급여·고정비가 포함된 실기기 계산과 마감본 다운로드는 아직 미검증이다.

마감·정정·출력 관련 Node/PGlite 검사 27개 통과. 기존 마감본의 불변 보존, 정정 이유와 새 버전, 재시도 요청 중복 방지, 일반 직원의 마감 차단, 아직 끝나지 않은 미래 월 마감 거부를 확인했다. 추가 UI 회귀검사에서 중복 마감 클릭 차단, 응답이 불확실한 마감의 동일 요청 ID 재사용, PDF 저장 취소·실패 후 마감 기록 유지 및 기록에서 재다운로드를 확인했다. 검사는 별도 로컬 합성 데이터로 실행했으며 사용자 매장 데이터나 운영 서버를 변경하지 않았다. 앱 수정 사항은 없어 재설치가 필요하지 않다.
