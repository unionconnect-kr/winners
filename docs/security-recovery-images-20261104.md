# Recovery reviewer MFA and receipt image validation — 2026-11-04

A service-role password recovery path checked a platform administrator's live session and role but omitted MFA. An AAL1 session could issue or reject recovery requests without using the hardened RLS helpers. The offline database test reproduces both actions against the exact deployed definitions before applying the fix.

The Edge now forwards the AAL from the exact token already verified by Auth, ignoring all client-supplied identity/session/AAL fields. The database requires both that claim and the persisted session AAL to be `aal2` for active platform administrators. An old AAL1 token remains invalid after the same session is elevated. Existing live-session, role, administrator-target and store-owner scope checks remain in place; ordinary owners can still recover their own staff's accounts at AAL1. Both RPC entry points remain service-role only.

Staging Edge v11 and production Edge v8 were deployed before the matching `recovery_reviewer_mfa` migration. The SQL checks the original definition hash, captures the previous function in the existing private backup table, and changes no account, password, session or business row. Rollback verifies the exact applied definition before restoring the original. Rollback reopens this MFA gap and is only an incident-recovery option. Operational source snapshots are deliberately excluded from the public repository. CI reconstructs its synthetic database fixture from the already versioned foundation and role rules; exact deployed definitions were separately tested before rollout. Staging's previously deployed SMS routing and stronger password rules have been reconciled into its repository source; production retains its own existing behavior.

Receipt processing now fully decodes static JPEG/PNG/WebP images with Sharp 0.35.5 after authorization and quota checks, rejects invalid images, caps input at 3 MiB / 16 million pixels, applies orientation, resizes to at most 2000×2000, and reencodes JPEG without original metadata before calling the provider. Native Sharp is externalized for this Netlify function. Original trailing bytes are not forwarded. This change only covers the receipt-to-AI path; database photo/PDF attachments retain structural validation and still need a dedicated full-content scanning pipeline.

Validation: 870 root tests, 860 passed, 10 integration tests skipped locally, 0 failed. New tests cover the pre-fix exploit, both actions and environments, old/missing AAL claims, wrong/expired sessions, disabled profiles, support vs administrator targets, owner vs another store, rollback and drift rejection; image decoding, metadata removal, MIME mismatch, fake headers, truncation, size/pixel bounds, and authorization-before-decoding/provider invocation. Production dependency audit: 0 known vulnerabilities. Provider calls are mocked; no real reset, SMS, push, AI charge or payment was performed. GitHub CI separately runs the PostgreSQL concurrency cases and build checks.

References: [Sharp constructor security bounds](https://sharp.pixelplumbing.com/api-constructor/), [Sharp output/metadata and timeout](https://sharp.pixelplumbing.com/api-output/), [Netlify function bundling](https://docs.netlify.com/build/functions/configuration/).

That Edge now rejects tokens below AAL2 and checks the platform-admin row using the verified user token and public application key, so the existing live-session RLS applies before any Auth account is created. Both bootstrap RPCs remain service-role only. Ordinary owner/staff signup is unchanged. Offline tests include a forged body AAL, invalid JWT, missing admin membership and a failed permission query. No real franchise account was created.
