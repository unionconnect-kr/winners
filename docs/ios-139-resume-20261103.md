# iOS 1.39 QA resumption — 2026-11-03

Android 1.39 had the current section 1–4 screens and role fixes, while the saved
iOS source ended at 0341c78 (2026-10-19). This change packages the exact 1.39
frontend baseline with the existing iOS shell and an explicit staging-only build.
The public web index, production database and App Store release remain unchanged.

## Changes

- `npm run build:ios139` builds the recovered Android 1.39 frontend for iOS.
  It refuses non-staging input and checks the source project and version.
- App/Browser callbacks return the user to the existing PKCE controller, with
  authorization origin/path checks and cold-launch handling. Info.plist registers
  the existing staging callback scheme. Provider/server readiness is not claimed.
- PDF/XLSX saves use the existing iOS share sheet; cancellation stays distinct.
  The native file validator now also permits manager CSV and contract PNG/JPEG.
- Staff/manager test notification routing checks live iOS membership and current
  role/store before showing the correct personal notification screen.
- Test billing and device-push controls explain that they are not connected.
  Actual StoreKit purchases and APNs delivery are not enabled by this QA build.
- The user explicitly approved code publication, signing and TestFlight upload
  on 2026-11-03. The existing permitted signing branch now builds staging 1.39.
  Other signing branches retain the production command. The existing upload
  authorization remains unchanged; a separately pinned upload will follow a
  successful archive. No store review submission or tester invitations are added.
