# Android 1.11 로그인·위치·알림 후속 검사

2026-10-13 사용자가 1.11 업데이트 설치를 확인했다. 직원·급여 일괄 검사 315개에 이어 로그인 복원과 기기 연결 경계를 검사했다.

## 자동 검사

10개 파일, 121개 중 119개 통과, 실패 0, 2개 건너뜀. 실제 Supabase JS SDK에 합성 네트워크 응답을 연결하여 이전 계정의 토큰 갱신이 새 로그인 계정을 덮어쓰지 않는지 확인했다. 로그인 유지 선택·저장소 소유권·재로그인·늦은 응답·권한 취소 매장 복원 차단을 검사했다.

Android 위치 어댑터에서 정확한 위치 권한, 좌표 유효성, 위치 정확도 100m 이하, 권한 거절·GPS 오류·시간 초과 처리 및 새 위치 요청을 검사했다. 알림 동의 없는 자동 권한 요청 방지, 동의 후 토큰 재등록, 로그아웃 정리, 알림 탭의 로그인 대기 및 계정 전환 무효화도 검사했다. 기기 API 응답은 모의 응답으로 제공했다.

초기 로그인 검사 6개가 테스트 VM에 ownerSetupStartupStep을 포함하지 않아 실패했다. 실제 앱에는 해당 함수가 존재한다. 테스트에 실제 준비 단계 함수들과 매장 ID 컨텍스트를 로드하여 보완했고 기존 계정 격리 단언을 유지한 채 전체 재실행에 통과했다. 앱 코드·APK는 변경하지 않았다.

## 미확인 범위

- 실제 PostgreSQL 동시 출퇴근 및 동시 직원 승인 2건은 MANEE_TEST_DATABASE_URL 미설정, 로컬 PostgreSQL 실행 도구 미설치로 건너뛰었다. 순차 합성 DB 검사를 실제 동시 접속 통과로 간주하지 않는다.
- 휴대폰의 실제 GPS 수신과 현장 100m 경계, OS 권한 화면 조작은 별도 기기 검증이 필요하다.
- 장시간 백그라운드 후 자동 갱신은 SDK 모의 검사와 구분한다.

이전 사용자 실기기 확인인 예약 등록·도착·취소 푸시, 알림 탭 이동, 잠정 PDF·엑셀 열기는 반복 요청하지 않는다. 이번 검사는 운영/스테이징 데이터를 수정하지 않았으며 새 APK 설치도 필요하지 않다.
