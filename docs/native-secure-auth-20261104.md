# Native auth storage hardening

New native builds keep remembered Supabase sessions and OAuth PKCE state in Android Keystore-backed AES-256-GCM storage or iOS device-only Keychain. Non-remembered sessions stay in native process memory; a WebView reload keeps them, while terminating the app process clears them. Environment-specific key names prevent staging and production state from mixing.

The existing account-switch/remember/logout adapter remains responsible for account ownership. Its synchronous view is hydrated before app initialization; Supabase's asynchronous storage wrapper awaits ordered native writes. Migration writes the old token into secure storage before removing the plaintext entry. A missing plugin, failed write, corrupt ciphertext or inaccessible Keychain blocks authentication initialization, with no fallback to plaintext storage. A durable non-secret logout tombstone is written before native deletion and retried on startup, so a failed deletion or process termination cannot rehydrate the old token. Users may need to restart the app if the OS storage is temporarily unavailable. OAuth browser handoff waits for its PKCE and pending-state writes.

Android binds ciphertext to the slot name using authenticated additional data, disables app backup and keeps keys non-exportable. iOS uses `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, disables synchronization and clears this app's Keychain service on first launch after reinstall. No credentials are logged. This protects stored data; it does not make a compromised running WebView unable to access its own session.

Scope: `build-web.mjs` and the iOS source build include the native bridge. The archived Android 1.41 web-over-old-native-shell packager is unchanged: that old shell cannot host a newly added Java plugin. A complete native rebuild and full feature/device regression are required before replacing that APK. This branch does not upload to either app store or replace production web behavior. Do not distribute the generic CI smoke-test APK as the current 1.41 feature-complete release.

Validation includes the real JavaScript account adapter with a mock native boundary (migration, remembered/transient storage, refresh/logout ordering, missing plugin and failed writes, OAuth state, environment isolation), Android emulator instrumentation for Keystore encryption/reload/delete/tamper checks, and the existing Android/iOS compilation workflows. Emulator and physical-device results must be reported separately; no signed store release is implied.
