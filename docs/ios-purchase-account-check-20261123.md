# iOS 계정 전환 후 구매·복원 검증

## 재현 증거와 범위

2026-11-23 오전 실제 iPhone의 TestFlight에서 사장님 계정을 전환한 후 Apple 구입 완료 화면이 표시됐지만, 심사용 매니 계정은 재실행 후에도 이용권 확인 필요 상태였다. 복원 결과는 현재 계정과 연결된 구매 없음이었다. 서버에서는 심사용 계정의 예전 만료 기록과 다른 매니 계정에 연결된 활성 Sandbox 구독을 확인했다. 요청 로그의 설치 빌드는 `156.21.1`이었다.

해당 구매의 서명된 거래 전문을 확보한 것은 아니므로 구매 응답의 정확한 거래 번호나 토큰을 단정하지 않는다. Apple의 구입 완료 화면은 매니 계정의 서버 검증·이용권 반영 성공을 의미하지 않는다.

이 수정은 `codex/ios-review-nov13`의 `64997d9b134ccbcb01563726031010524d4f8345`를 기준으로 분리했다. PC의 개발 중 미커밋 소스는 연결 장애로 비교하지 못했다. 운영 main에는 이 브랜치의 mobile 소스가 없으므로 그대로 운영 main에 병합하지 않는다. 현재 모바일 개발 브랜치에 필요한 변경만 통합하고 새 빌드를 검증해야 한다.

## 변경

- 구독 화면 진입 시 기기의 현재 거래와 서버가 허용한 계정별 상품·토큰 조합을 비교한다. 다른 계정에 연결된 동일 상품이면 재구매 버튼을 숨기고 원래 매니 계정으로 로그인하도록 안내한다.
- 구매 버튼 이후 Apple 계정이 달라지는 경우를 대비하여 native 진입 직전과 구매 응답에서 상품·계정 토큰을 다시 검사한다. 외부 계정의 거래는 서버 검증 요청이나 finish 대상으로 넘기지 않는다.
- 서버가 저장한 구매라도 활성 Production 또는 Sandbox 구독이 없으면 `purchased`로 반환하지 않는다. Sandbox는 기존 정책대로 테스트 구독이며 운영 쓰기 권한으로 승격하지 않는다.
- 복원 시 여러 거래 중 나중의 만료 거래가 이미 확인한 활성 결과를 덮지 않는다. 같은 매니 계정의 다른 매장에 속한 기존 토큰은 서버가 허용한 bindings에 있을 때 계속 복원할 수 있다.
- 복원 중 계정 충돌이 확인되면 상품 조회의 늦은 응답이 구매 버튼을 다시 표시하지 않는다.

구독 소유자, 기존 구매 토큰, 운영 이용권 및 결제 서버의 검증 규칙은 변경하지 않았다. Apple 시스템 화면 자체의 완료 문구를 변경하는 작업도 아니다. 앱에서 별도로 계정 적용 실패를 분명하게 표시한다.

## 검증

- `cd mobile && npm test`: 276개 통과.
- `node scripts/build-ios-release156.mjs ios production`: 생성 성공.
- `node scripts/verify-store-assets.mjs --ios-release156`: 통과.
- `git diff --check`: 통과.
- `.github/workflows/ios-purchase-account-check.yml`: 이 수정 브랜치만 대상으로 macOS에서 동일 테스트·생성 자산 검사·서명 없는 iOS 컴파일을 실행한다. 인증서, Apple 비밀키, 업로드 또는 심사 제출을 사용하지 않는다.

## 실제 기기 완료 조건

1. 기존 Apple 구매가 있는 기기에서 다른 매니 계정으로 진입한다. 다른 계정 연결 안내가 보이고 재구매가 차단되는지 확인한다.
2. 원래 구매한 매니 계정으로 돌아가 기존 구독을 복원한다. 활성 테스트 구독 표시가 재실행 후에도 유지되는지 확인한다.
3. 해당 상품의 기존 구매가 없는 Apple 테스트 환경과 매니 계정으로 신규 구독한다. Apple 완료 후 서버의 해당 계정에 Sandbox 활성 구독이 저장되고 앱도 같은 상태를 표시하는지 확인한다.
4. 취소 후 재시도, 서버 검증 실패 후 복원, 구매 도중 계정 변경을 확인한다. 실패 시 재구매를 유도하거나 다른 계정의 거래를 finish하지 않아야 한다.
5. iPhone 외에 이전 심사 기기 종류인 실제 iPad에서도 신규 구매와 복원을 확인한다.

코드·자동 테스트 완료는 TestFlight 배포 또는 실제 기기 통과가 아니다. Apple 신규 로그인에서 심사자가 SMS 가입을 완료할 수 있는지와 App Store Connect 심사용 비밀번호 일치는 별도로 해결해야 하며 이 수정으로 해결됐다고 표시하지 않는다.
