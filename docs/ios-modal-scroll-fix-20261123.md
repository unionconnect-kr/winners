# iOS 구독 팝업 배경 스크롤 수정 — 2026-11-23

## 문제와 변경

실제 TestFlight 화면에서 계정 이용권 팝업을 위아래로 밀면 뒤의 더보기 화면이 움직인다고 보고됐다. iOS 브리지는 dialog.showModal()만 호출했고 배경 스크롤 잠금은 없었다.

계정 이용권·매니 구독·앱 정보 팝업을 열기 전에 원래 스크롤 위치를 저장하고 배경을 같은 위치에 고정한다. 내용이 긴 팝업은 내부에서 계속 스크롤되며, 맨 위·아래에서 한 손가락으로 미는 동작이 배경으로 넘어가지 않게 처리했다. 닫기, 팝업 전환, 직접 DOM 제거 시 잠금 수와 원래 위치를 복원한다. 두 손가락 확대는 차단하지 않는다. 사장님용 계정 이용권 문구도 더보기에서 직접 구독 상태를 확인하도록 고쳤다.

## 검증 범위

- 모바일 자동 테스트 284개 통과. 짧은 팝업, 긴 팝업 양방향 스크롤과 경계, 내부 입력 영역 스크롤, 두 손가락 동작, 지연된 close 이벤트, 직접 제거, 실제 iOS 계정 이용권에서 구독 팝업으로 바꾸고 닫는 경로를 포함한다.
- 생산용 iOS 1.56 자산 생성과 검증 통과.
- WebKit에서 390px·820px 화면의 배경·팝업 경계·닫은 뒤 위치 복원 검증을 CI에 추가했다. 실행 결과는 별도로 확인해야 한다. 데스크톱 WebKit의 실제 휠 입력이며 iPhone의 실제 터치 검증을 대신하지 않는다.
- 로컬 브라우저 프로세스는 실행 환경의 소켓 제한으로 열지 못했다. 로컬 자동 테스트를 실제 브라우저 통과로 보고하지 않는다.
- 실제 iPhone에서 새 TestFlight 빌드를 설치한 후 배경 고정과 팝업 내부 스크롤을 재확인해야 한다.

결제 소유권·상품·서버 권한·운영 데이터는 이번 변경 범위에 포함하지 않았다. 정식 심사 제출은 하지 않는다.

## 브라우저 검사 재실행

첫 WebKit 실행에서 기존 페이지 검사는 1,968개 컨트롤을 확인하고 실패 없이 끝났다. 새 팝업 검사는 짧은 팝업의 배경 고정 검사 뒤 중첩된 details 두 개가 선택돼 테스트 선택자 오류로 중단됐다. 안내란 직계 자식만 지정하도록 검사 코드를 수정하고 팝업을 여는 순간의 위치도 검증한다. 앱 실행 코드와 CSS는 변경하지 않았으므로 156.24.1의 네이티브 수정본은 그대로다. 검사 코드 수정 커밋의 중복 서명 빌드는 생략하고, 이 문서 커밋으로 전체 PR 검사를 다시 실행한다.
