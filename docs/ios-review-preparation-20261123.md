# iOS 재심사 준비 — 2026-11-23

## 실제 기기에서 확인한 범위

TestFlight 1.56 (156.22.1)의 실제 iPhone에서 Apple 인증 후 이름·이메일 재입력 없이 가입 화면에 진입했고, 문자 수신·휴대폰 인증·사장님 신규가입·로그아웃 후 Apple 재로그인까지 완료했다. 기존 Apple 구매가 다른 매니 계정에 연결된 경우 재구매가 차단됐고 원래 매니 계정에서는 테스트 구독 인식과 복원 후 상태 유지가 확인됐다.

이는 새 Apple 구독을 구매하고 해당 매니 계정의 서버 이용권에 반영한 실험을 대신하지 않는다. 실제 iPad 검증도 아직 완료되지 않았다.

## 이번 준비

- iOS의 구독 거절 안내는 사장님에게 더보기의 구독 설정을 안내하고, 직원에게만 사장님 문의를 안내한다. 역할별 실행 테스트를 추가했다.
- 기존 심사 전용 가상매장 한 곳만 Sandbox 이용권 검증 환경으로 전환했다. 변경 전 Sandbox 매장은 0곳, 변경 후 1곳이다. 운영 결제는 계속 활성 상태이며 다른 매장은 Production 환경을 유지한다. 유효한 테스트 구매 없이 해당 심사 매장에 입력 권한을 부여하지 않았다.
- 심사용 계정의 비밀번호와 검증 안내는 App Store Connect API를 통해 준비한다. 비밀번호는 기존 Apple API 서명키의 공개키로 암호화한 자료만 저장소에 기록하고, 실행 환경 안에서 복호화해 정해진 앱·버전·심사 정보만 수정한다. 비밀키나 비밀번호는 로그로 출력하지 않는다. 읽기·쓰기 검증 도구는 배포 브랜치와 메타데이터 워크플로의 push 실행으로 제한된다.
- 이 작업은 심사 빌드 선택, 정식 심사 제출 또는 계정의 구매 소유권 이전을 수행하지 않는다.

## 아직 필요한 사항

1. 기존 구매 이력이 영향을 주지 않는 Apple Sandbox 결제 환경에서 신규 구매 → 서버 저장 → 심사 전용 매장 입력 권한 반영 → 재실행 후 유지까지 실제 기기에서 확인한다. 일반 Apple 계정의 기존 테스트 구독을 다른 매니 계정으로 옮겨 검증하지 않는다.
2. 심사자가 첫 Apple 가입을 직접 검수하려면 한국 번호의 SMS 인증 코드를 받을 수 있는 절차가 필요하다. 일반 사용자의 휴대폰 인증을 완화하거나, 클라이언트에 고정 인증번호를 넣거나, 유효기간이 짧은 실제 SMS 코드를 미리 심사 노트에 적는 것으로 해결됐다고 간주하지 않는다. 기존 만료 데모 계정으로 구매 흐름을 열고, 신규가입 SMS는 App Review 통화로 전달할 수 있도록 일정과 연락 절차를 정해야 한다.
3. App Store Connect에서 새 비밀번호 반영을 읽어 확인한 뒤에도, 실제 iPad의 신규 구매 및 심사자의 인증 절차가 준비되기 전에는 재제출 준비 완료로 보고하지 않는다.

- 모바일 테스트 277개 통과.
- 심사정보 암호화·수정 범위·읽어 확인하기 테스트 6개 통과.
- iOS 생성 자산과 서명 빌드 결과는 각각의 실행 결과로 확인한다.
