# iPhone form and layout review — 2026-11-03

The iPhone build inherited native WebKit select/date/time appearance, making selects shorter than neighboring text fields and shrinking date/time fields to their contents. Shared iPhone overrides now use 48px controls, 16px medium text, consistent padding, and a single chevron. Textareas, file inputs and close buttons follow the same spacing. Android release assets remain archived unchanged.

Safe-area ownership is explicit: viewport-fit=cover, Capacitor contentInset=never, CSS safe-area spacing and a fixed status-bar background. The test notice has reserved space and the duplicate environment notice is hidden. Modal height excludes top/bottom safe areas and the notice.

Validation: 90 existing mobile tests pass. Offline WebKit renders 44 fixtures at 320, 375, 390 and 430 CSS pixels (176 cases); 60 rendered select/date/time instances satisfy height/font/appearance checks, with no form or dialog horizontal overflow. Fixtures include all eight onboarding steps, five owner main sections, nine staff and nine manager views, reservation/expense sheets, notices, checklist management, account/password/support and entry screens. Synthetic top/bottom safe areas are 47px/34px; five representative screenshots were visually inspected.

Run after npm run build:ios139, with Playwright/WebKit available:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright IOS_UI_AUDIT_OUT=/tmp/manee-ui-review node mobile/scripts/audit-ios-ui.mjs
```

This is a presentation audit with synthetic data. It does not replace on-device checks of the iOS status bar, keyboard, native picker and rotation, or live authorization and server mutations. Those interactions are not claimed as completed by these fixtures.
