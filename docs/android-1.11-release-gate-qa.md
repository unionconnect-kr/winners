# Android 1.11 전체 자동 검사 연결

2026-10-13 KST. 사용자의 반복 수동 확인 부담을 줄이기 위해 APK 생성 전 자동 검사 범위를 통합했다. 앱 기능 코드와 APK는 변경하지 않았다.

## 변경

- Android staging APK workflow에 선행 regression 작업을 추가했다. 별도 PostgreSQL 17 서비스에서 매장 코드·직원 승인·출퇴근 동시 요청 검사를 순차 준비 후 실행한다. 각 검사 내부의 요청은 동시에 실행한다.
- 실제 DB 검사 3개가 모두 통과하고 건너뜀 없이 끝나야 통과한다. 명시적 TAP 출력, 환경 변수 필수 검사, pipefail, 요약 검증을 사용한다. 실패·누락·건너뜀을 거부하는 요약 검증을 합성 로그로 확인했다.
- 전체 앱·보안 검사가 통과해야 기존 네이티브 검사 및 APK 빌드 작업을 실행한다. 테스트·보안·공통 스크립트·루트 의존성 변경도 workflow 실행 경로에 포함했다. 결과 로그는 CI artifact로 보관한다.

## 기존 검사 보완

최초 전체 실행: 833개 중 806개 통과, 17개 실패, 10개 건너뜀. 실패 원인은 다음과 같다.

- 월 보고서 렌더링용 VM 3곳에 monthKey, renderReportExportStatus와 매장 컨텍스트가 없었다. 실제 함수들을 로드하도록 수정했으며 금액·비율·오류 상태 검증은 유지했다.
- 직원 등록 검사의 코드 문자열과 보존 해시가 1.11의 중복 방지·컨텍스트 보호·급여 검증 변경 전 상태였다. 함수 변경을 검토한 뒤 기준을 갱신했다. 실제 등록 함수로 고용 정보 보존, 인증 모드에서 레거시 코드 미생성, 레거시 모드의 코드 생성·저장을 추가 검증했다.
- 헤더 검사가 매장 선택 HTML을 함수 밖에서 찾고 있었다. 분리된 렌더 함수 호출 순서와 실제 단일/복수 매장 출력 동작을 검사하도록 보완했다.

## 결과

- 앱·보안 전체: 836개 중 **826개 통과, 실패 0, 건너뜀 10**.
- 네이티브 전체: **23개 통과, 실패 0, 건너뜀 0**.
- 합계: **849개 통과, 10개 미실행**. 부분 재검사 95개는 중복 합산하지 않았다.
- YAML 파싱, APK 선행 작업 연결, diff 공백 검사 완료.

미실행 10개는 실제 PostgreSQL 동시 접속 3개, PostgreSQL 백업 도구를 요구하는 백업·복원 6개, 실제 스테이징 백업을 요구하는 복원 1개다. 운영/스테이징 데이터는 접근·수정하지 않았다. 실기기 GPS, 장시간 백그라운드 동작, 실제 서버에서의 동시 요청은 이 결과로 확인했다고 볼 수 없다.

## 반영 상태

변경은 로컬 저장소에 준비했다. 이전 자동 승인 검토가 명시적 소스 게시 승인 없는 GitHub 업로드를 거부했으므로 push 또는 우회 업로드는 하지 않았다. GitHub workflow의 실제 실행 결과는 아직 없다. 원격 반영과 workflow 실행 전까지 자동 APK 검사 절차가 활성화됐다고 표현하지 않는다.

사용자는 1.11을 유지하며, 이번 변경 때문에 새 APK 설치나 기존 확인 화면의 재전송을 할 필요가 없다.

## 2026-10-14 GitHub 실행 후속

사용자가 개발 브랜치 업로드와 자동 검사 실행을 승인했다. 회사 GitHub 연결로 PR #21의 개발 브랜치에 b276a1b를 반영했고 로컬 검증본과 Git tree가 일치함을 확인했다. 터미널 push는 로그인 정보 부재로 실패했으며 연결된 회사 계정을 사용했다.

첫 원격 실행 38419195544에서 PostgreSQL 17 동시 요청 검사 3개가 모두 통과했다(각 1개 통과, 0개 건너뜀). 12개 출퇴근 동시 요청, 직원 신규 승인 경쟁 및 재시도, 매장 코드 할당·승인 경쟁을 실제 분리된 DB 연결로 검증했다. 운영/스테이징 DB는 사용하지 않았다.

전체 앱 검사에서는 엑셀 검사 파일이 mobile/node_modules/xlsx-js-style을 찾지 못해 실패했다. 선행 작업에 루트 의존성만 설치한 것이 원인이므로 Android 및 동일 검사를 실행하는 store-code workflow에 mobile 의존성 설치를 추가했다. 검사 제외나 오류 무시는 하지 않았다. 이 보완의 최종 결과는 PR #21의 최신 Actions 실행을 기준으로 확인한다. 백업·복원 7건과 실기기 GPS/장시간 백그라운드는 여전히 별도 확인 범위다.

두 번째 원격 실행 38419767512에서 앱·보안 826개와 실제 DB 동시 요청 3개가 통과했다. APK 단계는 setup-android@v3의 기본 설치 항목인 구형 `tools`를 SDK 저장소에서 찾지 못해 중단됐다. Action의 공식 action.yml을 확인하고 필요한 platform-tools, Android 36 플랫폼, build-tools 36.0.0을 명시하도록 수정했다. 새 CI APK는 별도 Firebase 설정 및 고정 서명을 주입하지 않는 컴파일 검증 산출물이므로 사용자에게 배포한 1.11 APK를 대체하는 업데이트로 안내하지 않는다.
